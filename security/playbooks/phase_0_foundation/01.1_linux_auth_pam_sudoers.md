## 🚨 案發現場破題 (The Incident Scenario)

> **情境帶入**：  
> 週三深夜 23:40，主機入侵偵測系統（HIDS / OSSEC）發出警報：核心生產環境的 Linux 應用伺服器 `app-prod-01` 上，一個名為 `www-data` 的低權限 Web 服務帳號，竟然成功切換為 `root` 執行了特權指令！  
> 
> 維運工程師驚訝地反駁：「這不可能！我們從來沒有把 `root` 密碼給過開發者，這台機器也嚴格禁止密碼登入，只能用 SSH Key！而且 `/etc/passwd` 裡 `root` 的 Shell 明明都是正常的！」  
> 
> 你透過緊急審計通道連入伺服器。  
> 檢查 `/var/log/auth.log`，你發現了極度詭異的痕跡：攻擊者透過 Web 漏洞上傳了一句話木馬後，輸入了一行看似無害的指令 `sudo -u root /usr/bin/find ...`，瞬間就拿到了一個不需要密碼的 Root Shell。  
> 更可怕的是，當你嘗試修改 `/etc/shadow` 或檢查 PAM 驗證模組時，發現即使輸入錯誤密碼，某些特定的使用者竟然也能成功通過驗證！  
> 
> 這是典型的 **Sudoers 配置不當提權（Misconfigured Sudoers Privilege Escalation）**？還是黑客在系統底層植入了惡意的 **PAM 後門（PAM Backdoor）**，繞過了整個 Linux 的身分驗證體系？
>
> **本手冊的使命**：帶你深入 Linux 身分認證與權限控制的底層心臟，從 `/etc/passwd`、`/etc/shadow` 的每段欄位含義，到 PAM（可插入式認證模組）的堆疊機制，再到 Sudoers 的危險配置，用精準指令徹底清查非法提權與隱藏後門。

## 🧩 第一動：底層機制解剖——Linux 是如何驗證身分與授權特權的？

在 Linux 系統中，身分認證（Authentication）與特權授權（Authorization）是由兩個不同但緊密合作的子系統完成的：**PAM 負責「證明你是誰」，Sudo 負責「允許你做什麼」**。

### 1.1 Linux 核心帳號與密碼資料庫（`/etc/passwd`、`/etc/shadow` 與特權位元）

Linux 系統不以使用者名稱區分權限，**核心只認 UID（User ID）。UID 0 擁有系統最高無上特權**！

```
[/etc/passwd 7 大欄位完整解構]
root:x:0:0:root:/root:/bin/bash
 │   │ │ │   │     │      └─ 7. Default Shell (登入後啟動的 Shell，/bin/false 或 /usr/sbin/nologin 代表禁止互動登入)
 │   │ │ │   │     └──────── 6. Home Directory (家目錄路徑)
 │   │ │ │   └────────────── 5. GECOS (備註資訊，如使用者全名、辦公室電話)
 │   │ │ └────────────────── 4. GID (主要群組 ID，對應 /etc/group)
 │   │ └──────────────────── 3. UID (★ 使用者 ID！若被黑客篡改為 0 即具備 Root 權限！)
 │   └────────────────────── 2. Password Placeholder ('x' 代表密碼經雜湊後存放在 /etc/shadow)
 └────────────────────────── 1. Username (帳號名稱)

[/etc/shadow 9 大欄位完整解構 (藍隊稽核必背)]
admin:$6$saltsalt$hashedpassword...:19750:0:90:7:30:19900:
  │   └──────────────┬────────────┘   │   │  │ │  │    │   └─ 9. Reserved (保留未用)
  │                  │                │   │  │ │  │    └───── 8. Expiration Date (帳號徹底失效日，自 1970-01-01 起算天數)
  │                  │                │   │  │ │  └────────── 7. Inactivity Days (密碼過期後寬限期，過後帳號鎖定)
  │                  │                │   │  │ └───────────── 6. Warning Days (密碼過期前幾天開始告警，通常為 7 天)
  │                  │                │   │  └─────────────── 5. Maximum Days (密碼有效最長天數，通常為 90 天)
  │                  │                │   └────────────────── 4. Minimum Days (密碼修改後最短需維持天數，0 代表隨時可改)
  │                  │                └────────────────────── 3. Last Changed (最後一次變更密碼日期，自 1970-01-01 起算天數)
  │                  │
  │                  └─ ★ 密碼欄位狀態判斷（藍隊重點清查！）：
  │                     • $6$... : 正常已加密密碼 ($6$ 代表 SHA-512, $y$ 代表 Yescrypt, $1$ 代表 MD5)
  │                     • ! 或 * : 帳號已被【鎖定/停用】(Password Locked)，無法密碼登入
  │                     • !!     : 帳號剛建立但尚未設定密碼
  │                     • (空)   : 【致命弱點】無密碼帳號 (Null Password)，直接按 Enter 即可登入！
  └──────────────────── 1. Username (對應 /etc/passwd 的帳號)

[Linux 檔案特殊權限位元：SUID / SGID / Sticky Bit 提權原理]
      rws  r-x  r-x    (八進位: 4755 -> SUID)
      ││   │    │
      ││   │    └─ Other: 具備讀取與執行權
      ││   └────── Group: 具備讀取與執行權
      │└────────── User Execute 變成 's' (SUID 啟用！以檔案擁有者權限執行)
      └─────────── User Read/Write
  
  ┌───────────────┬────────────────────────────────────────────────────────┐
  │ 特殊位元 (Octal)│ 核心機制與資安意圖 (GTFOBins 提權核心)                  │
  ├───────────────┼────────────────────────────────────────────────────────┤
  │ 4000 (SUID)   │ 任何使用者執行該二進位檔時，臨時獲得【檔案擁有者(Owner)】權限！ │
  │               │ 若 Owner 為 root，普通使用者執行即可暫時化身為 root！   │
  ├───────────────┼────────────────────────────────────────────────────────┤
  │ 2000 (SGID)   │ 執行時臨時獲得【所屬群組(Group)】權限，常掛於目錄傳承 GID。│
  ├───────────────┼────────────────────────────────────────────────────────┤
  │ 1000 (Sticky) │ 僅允許檔案擁有者與 root 刪除檔案 (如 /tmp 目錄設為 1777)。│
  └───────────────┴────────────────────────────────────────────────────────┘
```

### 1.2 PAM（Pluggable Authentication Modules）堆疊機制

當你執行 `su`、`sudo` 或透過 SSH 登入時，程式不會自己去寫驗證密碼的程式碼，而是呼叫 **PAM 模組庫**（設定檔位於 `/etc/pam.d/`）：

```
[應用程式請求 (如 sudo / sshd)]
           │
           ▼
[/etc/pam.d/ 對應設定檔]
  ├── auth      : 身分認證（確認使用者是誰，如要求輸入密碼/MFA）
  ├── account   : 帳號有效性（檢查密碼是否過期、帳號是否遭停用）
  ├── password  : 密碼更新（修改密碼時的複雜度校驗）
  └── session   : 環境建立與清理（掛載家目錄、記錄登入稽核）

[PAM Control Flags (控制標記) 致命規則]
• required    : 必須成功。若失敗，整條鏈必然失敗，但會繼續跑完後續模組（防止定時攻擊）。
• requisite   : 必須成功。若失敗，【立即終止】並返回錯誤！
• sufficient  : 【充分條件】！若此模組成功且前面沒有 required 失敗，【立即判定通過】！
• optional    : 參考用，結果通常不影響大局。
```
> ⚠️ **後門黑客的最愛**：黑客只要在 `/etc/pam.d/common-auth` 最頂端偷偷插入一行：  
> `auth sufficient pam_permit.so` 或加載自定義的惡意 `.so`，**整個系統所有帳號任何密碼都能直接登入**！

## 🧭 第二動：解碼意圖——帳號安全與提權異常速查表

在排查 Linux 伺服器時，你該如何依據設定檔與日誌判定系統是否已被動手腳？

### 2.1 Linux 認證與授權異常速查表

| 設定與日誌特徵現象（看到什麼） | 底層成因與攻擊手法（是什麼攻擊） | 威脅影響與處置優先級（怎麼應對） |
| :--- | :--- | :--- |
| **`/etc/passwd` 中除 root 外出現第二個 UID 為 0 的帳號** | **隱藏後門帳號（Superuser Backdoor）**：<br>黑客手動建立了一個非 root 命名的帳號（如 `toor` 或 `sysadmin`），但將其 UID 強行設為 0。 | • **影響**：攻擊者獲得等同 root 的隱密永久後門。<br>• **優先級**：緊急（立即自 `/etc/passwd` 刪除該帳號）。 |
| **Sudoers 配置允許免密碼執行特權二進位檔（如 `ALL=(ALL) NOPASSWD: ALL`）** | **超限授權或特權失控**：<br>維運或開發人員為了方便，將整台機器的無密碼 root 執行權限開放給普通使用者。 | • **影響**：該普通帳號一旦失陷，黑客 1 秒獲取 Root。<br>• **優先級**：高（撤銷 `NOPASSWD: ALL` 規則）。 |
| **Sudo 允許執行可逃逸二進位檔（如 `find`, `vim`, `less`, `awk`）** | **GTFOBins 特權逃逸（Sudo Escape）**：<br>Sudo 雖然限制只能執行特定命令，但這些二進位檔案自帶 Shell 逃逸或讀寫任意檔案功能（如 `sudo find -exec /bin/sh \;`）。 | • **影響**：繞過限制直接獲取互動式 Root Shell。<br>• **優先級**：高（嚴禁使用 sudo 授權編輯器或具有執行命令功能的工具）。 |
| **`/etc/pam.d/` 檔案的修改時間異常，出現未知 `.so` 模組** | **PAM 惡意認證後門（PAM Backdoor）**：<br>黑客替換了 `pam_unix.so`，或新增了萬能密碼（Master Password）模組，無論何時輸入特定字串均無條件放行。 | • **影響**：整個作業系統身分驗證體系完全崩潰。<br>• **優先級**：緊急（使用套件管理器 `dpkg -V` 或 `rpm -V` 恢復原始 PAM 模組）。 |
| **`/etc/shadow` 中帳號的密碼欄位為空或為 `!`** | **空密碼風險或鎖定狀態**：<br>`!` 或 `*` 代表該帳號已被停用/鎖定；若為空字串，代表該帳號任何人免密碼即可登入。 | • **影響**：空密碼帳號極易遭本機橫向提權。<br>• **優先級**：中至高（清查並強制設置密碼或設定 nologin）。 |

## 💻 第三動：現場追兇——Linux 現場終端排查指令

身為現場調查員，你必須在終端機使用原生工具極速揪出潛伏在帳號與授權中的地雷。

### 3.1 核心帳號庫與 UID 0 清查

#### 步驟 1：抓出所有 UID 為 0 的超級特權帳號
```bash
# 正常情況下，輸出應該只有唯一一行 'root'
awk -F: '($3 == 0) {print "超級使用者帳號: " $1 ", UID: " $3}' /etc/passwd
```

#### 步驟 2：清查是否有無密碼的「裸奔帳號」
```bash
# 檢查 /etc/shadow 中第二欄為空的帳號
sudo awk -F: '($2 == "") {print "⚠️ 警告：發現無密碼帳號 -> " $1}' /etc/shadow
```

#### 步驟 3：清查擁有互動式登入 Shell（如 /bin/bash, /bin/sh）的非系統帳號
```bash
# 排除 /usr/sbin/nologin 與 /bin/false，找出所有能真實登入的實體帳戶
egrep -v "nologin|false" /etc/passwd | cut -d: -f1,3,7
```

### 3.2 Sudoers 權限漏洞與危險配置清查

#### 步驟 1：檢視目前使用者具備的 Sudo 授權
```bash
# 檢查自身可執行的特權指令（重點尋找 NOPASSWD 與危險二進位檔）
sudo -l
```

#### 步驟 2：全局搜尋所有 Sudoers 設定檔中的危險萬用字元
```bash
# 檢查主設定檔與 /etc/sudoers.d/ 目錄下的所有自定義規則
grep -Eiq "(ALL.*NOPASSWD|NOPASSWD.*ALL)" /etc/sudoers /etc/sudoers.d/* 2>/dev/null && \
echo "🚨 發現高危無密碼全特權授權！" || echo "🟢 未發現通用 NOPASSWD: ALL 規則"
```

#### 步驟 3：檢查常見 GTFOBins 危險特權命令（Sudo 提權殺手）
若在 `sudo -l` 中看到以下任何一個程式被賦予特權，黑客即可秒殺提權：
```bash
# 若允許 sudo find：
sudo find . -exec /bin/sh \; -quit

# 若允許 sudo vim：
sudo vim -c ':!/bin/sh'

# 若允許 sudo awk：
sudo awk 'BEGIN {system("/bin/sh")}'

# 若允許 sudo less / more：
sudo less /etc/hosts   # 進入後輸入 !/bin/sh 即可獲得 Root
```

### 3.3 PAM 模組完整性與防篡改校驗

懷疑黑客植入了 PAM 萬能密碼後門？利用官方套件管理器的哈希驗證機制進行對比：

```bash
# Debian / Ubuntu：驗證 PAM 套件中的所有二進位檔案與設定檔是否遭竄改
dpkg -V libpam-modules libpam-runtime

# RHEL / CentOS / Rocky Linux：驗證 pam 套件
rpm -V pam

# 檢查最近 3 天內被修改過的 PAM 設定檔
find /etc/pam.d/ -type f -mtime -3 -ls
```

## ⚖️ 第四動：研判分水嶺——維運緊急變更 vs 惡意提權？

在實際維運環境中，工程師有時會為了自動化部署（如 Ansible）暫時加入免密碼規則。你該如何區分是內部正規維運還是黑客攻擊？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | `/var/log/auth.log` 或 `/var/log/secure` 出現非預期的 `sudo` 提權執行，或 PAM 認證連續異常。 |
| **Q2. 來源主體**（誰執行了該提權動作？） | 執行 Sudo 的原始帳號是實體員工帳號（如 `john`），還是無互動權限的系統服務帳戶（如 `www-data`, `nobody`, `apache`）？服務帳號提權 **99% 為 Web 漏洞入侵！** |
| **Q3. 提權指令**（執行的具體命令是什麼？） | 是維運例行的 `systemctl restart nginx`，還是直接呼叫 `/bin/bash`、`find -exec`、`curl | sh`？ |
| **Q4. 認證脈絡**（登入來源是哪裡？） | 檢視該帳號的前置登入日誌：是否有正規的 SSH 登入記錄？還是直接由 Apache/Nginx 子進程衍生（WebShell 跡象）？ |
| **Q5. 設定變更**（Sudoers 是否剛被編輯過？） | 檢查 `/etc/sudoers` 與 `/etc/sudoers.d/` 的檔案修改時間（mtime），是否與工單系統的變更窗口相吻合？ |
| **Q6. 攻擊成果**（攻擊者是否已獲取 Root？） | 檢查進程樹（Process Tree）：在 sudo 之後是否掛載了持續運行的 `/bin/sh` 或連往外部公網的 Reverse Shell？ |
| **Q7. 橫向波及**（其他伺服器是否有一樣的變更？） | 檢查組態管理工具（Ansible/Puppet）：該危險 Sudoers 規則是否被大量推送到全網主機？ |
| **Q8. 處置動作**（下一步是什麼？） | 1. 立即從 Sudoers 中移除危險條目；2. 終止異常特權進程；3. 鎖定受害帳號（`passwd -l <user>`）。 |

## 🛡️ 第五動：加固防禦與收斂 SOP (Mitigation & Hardening)

確認存在權限失控或惡意提權跡象時，依循以下標準作業程序進行防禦收斂：

### 1. 拔除危險 Sudo 授權並嚴格限定參數
- **嚴禁在 Sudoers 中使用萬用字元 `*`**：例如配置 `john ALL=(ALL) /bin/cat /var/log/*` 看似安全，但攻擊者只要執行 `sudo cat /var/log/../../etc/shadow` 即可讀取全機密碼雜湊！
- **使用 `visudo` 進行語法校驗**：切勿直接用 `vim` 編輯 `/etc/sudoers`，務必使用 `sudo visudo`，防止語法錯誤導致全機無法使用 sudo。

### 2. 部署 PAM 密碼暴力破解鎖定策略
在 `/etc/pam.d/common-auth`（RHEL 為 `/etc/pam.d/system-auth`）加入 `pam_faillock` 模組，防止本機密碼爆破：

```bash
# 密碼輸錯 5 次鎖定帳號 15 分鐘（900 秒）
auth required pam_faillock.so preauth audit silent deny=5 unlock_time=900
auth [default=die] pam_faillock.so authfail audit deny=5 unlock_time=900
account required pam_faillock.so
```

### 3. 緊急鎖定可疑帳號
```bash
# 立即鎖定帳號（在 /etc/shadow 密碼前加上 !）
sudo passwd -l <username>

# 強制殺死該帳號目前所有線上的進程與連線會話
sudo pkill -u <username>
```
