## 🧩 第一動：底層協定解剖——DNS 為何能成為黑客的「隱密高速公路」？

DNS（Domain Name System）採用 UDP 53 通訊埠（大型回應時切換為 TCP 53）。在絕大多數企業架構中，內網電腦向內部 DNS 伺服器查詢是**完全被信任且預設放行**的，這給了攻擊者可乘之機。

### 1.1 DNS Tunneling（通道外洩）底層傳輸原理

攻擊者不需要直接連線到公網。他只需要註冊一個由他控制的權威名稱伺服器（Authoritative Name Server）：

```
[受害主機 (受隔離)]                 [企業內部 DNS]                 [黑客權威 DNS (公網)]
       │                                  │                                  │
       │ 1. 偷取資料並 Base32 編碼        │                                  │
       │    Query: <DATA>.attacker.com    │                                  │
       │ ───────────────────────────────> │                                  │
       │                                  │ 2. 遞迴轉發查詢 (合法放行)       │
       │                                  │ ───────────────────────────────> │
       │                                  │                                  │ 3. 黑客收到並解碼
       │                                  │ 4. 回覆 TXT/CNAME 夾帶 C2 指令   │    還原外洩資料！
       │                                  │ <─────────────────────────────── │
       │ 5. 收到 C2 指令並執行            │                                  │
       │ <─────────────────────────────── │                                  │
```

- **上行資料外洩（Exfiltration）**：受害主機將檔案切片、編碼（Base32/Base64/Hex）後，拼裝在「子網域名稱」中送出（例如：`TXkgU2VjcmV0.tunnel.evil.com`）。
- **下行遠端控制（Command & Control）**：黑客權威伺服器將執行指令（如 `whoami`、Payload Shellcode）包裝在 `TXT` 記錄、`CNAME` 記錄或 `NULL` 記錄中回覆給受害端。

---

### 1.2 DGA（網域名稱生成演算法）通訊原理

不同於 Tunneling 外洩大量資料，**DGA 的目的在於「逃避黑名單封鎖」**。
- 惡意程式內建一段數學演算法，以「當前日期（種子 Seed）」作為輸入，每天自動計算生成數千個隨機網域名稱（例如：`xqj83kas91.biz`、`plm92nxz71.org`）。
- 黑客只要預先算好今天會生成哪一個域名，搶先註冊其中 1~2 個，即可成功與受感染主機取得聯繫。
- **鑑識特徵**：內部主機會在短時間內產生大量 `NXDOMAIN`（域名不存在，RCODE=3）的查詢失敗記錄。

## 💻 第三動：現場追兇——Wireshark 與 SIEM 實戰指令

身為現場調查員，你必須迅速鎖定惡意通道的流量特徵並還原傳輸內容。

### 3.1 Wireshark 顯示過濾器精準語法

#### 語法 1：找出異常長度的 DNS 查詢名稱（Tunneling 核心指標）
```wireshark
# 篩選 DNS 查詢名稱長度大於 50 字元的異常封包（一般正常網址很少超過 35 字元）
dns.qry.name.len > 50
```

#### 語法 2：篩選所有 TXT 記錄與異常大體積的 DNS 回應
```wireshark
# 篩選查詢類型為 TXT (Type 16) 或回應內容大於 200 bytes 的封包
dns.qry.type == 16 || dns.resp.len > 200
```

#### 語法 3：抓出所有查詢失敗（NXDOMAIN，尋找 DGA 特徵）
```wireshark
# 篩選 RCODE 為 3 (Non-Existent Domain / NXDOMAIN) 的封包
dns.flags.rcode == 3
```

#### 語法 4：依子網域數量統計（尋找 Tunneling 父網域）
```wireshark
# 找出所有包含特定疑似 C2 根網域的請求
dns.qry.name contains "attacker-c2.com"
```

### 3.2 Python 計算網域名稱夏農熵（Shannon Entropy）現場腳本

當你在 SIEM 或 PCAP 抓出大量網域名稱時，用以下 Python 腳本計算資訊熵。**熵值大於 3.8 ~ 4.0 者，幾乎必為加密外洩字串或 DGA**：

```python
import math
from collections import Counter

def shannon_entropy(domain: str) -> float:
    # 僅計算子網域名稱部分的混亂度
    subdomain = domain.split('.')[0]
    length = len(subdomain)
    if length == 0:
        return 0.0
    counts = Counter(subdomain)
    entropy = -sum((count / length) * math.log2(count / length) for count in counts.values())
    return round(entropy, 3)

# 測試範例
domains = [
    "google.com",                                      # 正常常見域名
    "login.microsoftonline.com",                       # 正常較長域名
    "a8f3b9c1e7d41d8cd98f00b204e98009.attacker.com",   # DNS Tunneling 外洩資料
    "xqj83kas91nxz.biz"                                # DGA 隨機生成
]

for d in domains:
    score = shannon_entropy(d)
    verdict = "🚨 疑似惡意/加密 (High Entropy)" if score > 3.8 else "🟢 正常/規律"
    print(f"[{score}] {d:<50} -> {verdict}")
```

### 3.3 Splunk SPL 大規模威脅獵捕

#### 偵測情境 A：獵殺高頻超長 DNS 查詢（Tunneling 外洩偵測）
```splunk
index=dns sourcetype="stream:dns"
| eval query_len=len(query)
| where query_len > 50
| stats count, dc(query) as unique_subdomains, avg(query_len) as avg_len by src_ip, parent_domain
| where unique_subdomains > 100 AND count > 500
| eval Alert_Level="🚨 CRITICAL: DNS Tunneling Exfiltration Suspected"
| sort - count
```

#### 偵測情境 B：獵殺突發大量 NXDOMAIN（DGA 感染主機定位）
```splunk
index=dns sourcetype="stream:dns" rcode="NXDOMAIN"
| bin _time span=10m
| stats count as nx_count, dc(query) as distinct_failed_domains by src_ip, _time
| where distinct_failed_domains > 50
| eval Alert_Level="🔴 HIGH: DGA Activity / C2 Hunting Detected"
| sort - distinct_failed_domains
```

## ⚖️ 第四動：研判分水嶺——正常業務 vs 惡意通道？

在現代企業中，某些安全軟體（如防毒軟體雲端即時查毒、垃圾郵件過濾器 DNSBL）也會發送超長或高頻的 DNS 查詢。你該如何區分？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | 單一來源主機在短時間內發送大量異常長度子網域，或 NXDOMAIN 比例突破 40%。 |
| **Q2. 來源實體**（誰/哪個 IP 發起的？） | `src_ip` 是一般辦公電腦、資料庫伺服器，還是對外郵件網關（Mail Gateway）？ |
| **Q3. 目標域名**（查詢的父網域是誰？） | 提取二級域名（SLD）：是知名資安廠商（如 `*.spamexperts.com`、`*.trendmicro.com`），還是剛註冊幾天的陌生網域（Whois Age < 14 天）？ |
| **Q4. 查詢類型**（請求的 Record Type 為何？） | 是標準的 A 記錄，還是極其罕見的大量 TXT、NULL、CNAME 記錄請求？ |
| **Q5. 資訊亂度**（子網域的文字特徵？） | 檢視字元集：是 Base32/Base64/Hex 編碼？母音與子音分佈是否違反人類自然語言規律（夏農熵 > 3.8）？ |
| **Q6. 攻擊成果**（通道是否已經建立？） | 是否有成功收到非 NXDOMAIN 的真實解析（NOERROR），代表 C2 已經連上或資料已經成功送達黑客伺服器？ |
| **Q7. 橫向波及**（是否有多台機器受害？） | 全網 SIEM 檢查，該父域名是否同時被其他主機發送查詢？若有多台，屬於全網性 APT 爆發。 |
| **Q8. 處置動作**（下一步是什麼？） | 1. DNS 伺服器端立即下發 RPZ（響應原則區域）將該惡意父域名指向 Sinkhole（黑洞）；2. EDR 隔離發起源主機進行惡意進程調查。 |

## 🛡️ 第五動：阻斷與加固 SOP (Mitigation & Hardening)

一旦確認為 DNS Tunneling 或 DGA 活動，立即採取以下四道阻斷與加固防線：

### 1. 應急處置：DNS Sinkhole 與 RPZ 阻斷
- **RPZ（Response Policy Zone）**：在企業內部 DNS 伺服器（如 BIND, Windows Server DNS）直接設定 RPZ 策略，將惡意父網域（如 `*.attacker-c2.com`）解析結果強制改寫為 `0.0.0.0` 或重定向至內網安全分析機（Sinkhole）。
- **網關封鎖**：在防火牆直接阻斷內部未授權主機繞過內網 DNS 直連外部公網 DNS（阻斷所有非 DNS 伺服器對外的 UDP/TCP 53 流量）。

### 2. 端點排查：定位惡意進程（Process Hunting）
拿著觸發惡意查詢的來源主機 IP，登入該機終端執行排查：

```powershell
# Windows: 檢視目前是哪一個進程或服務正在維持網路活動或 DNS 快取
Get-DnsClientCache | Where-Object { $_.Entry -like "*attacker*" }

# 查看佔用網路連線的進程 PID
netstat -ano | findstr ":53"
```

  4. 統計黑客建立該惡意通道所使用的 DNS 查詢類型（A, TXT 還是 NULL）。
