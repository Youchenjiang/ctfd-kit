## 🧩 第一動：底層協定解剖——TLS 握手與 JA3 指紋誕生原理

在 HTTPS 流量建立安全加密通道前，雙方必須先進行**明文**的參數協商。黑客就算能加密連線內容，也**無法掩蓋其作業系統通訊庫（如 OpenSSL、WinINet、Go-net/http）在連線初期所暴露的專屬語法結構**。

### 1.1 TLS 1.2 / 1.3 握手流程與明文暴露面

```
[Client]                                              [Server]
   │                                                     │
   │ 1. [Client Hello] (完全明文！)                       │
   │    • TLS Version (e.g. TLS 1.2 / 1.3)               │
   │    • Supported Cipher Suites (加密套件列表順序)      │
   │    • Extensions (擴展功能，如 SNI 伺服器名稱)        │
   │    • Elliptic Curves (橢圓曲線演算法支援)           │
   │    • EC Point Formats (曲線點格式)                  │
   │ ──────────────────────────────────────────────────> │
   │                                                     │
   │ 2. [Server Hello] (完全明文！)                       │
   │    • Selected Cipher Suite (選定的加密套件)         │
   │    • Server Certificate (伺服器數位憑證！)          │
   │ <────────────────────────────────────────────────── │
   │                                                     │
   │ 3. 金鑰交換與協商完畢 (後續所有傳輸完全加密！)        │
   │ <=================================================> │
```

---

### 1.2 JA3 指紋是如何計算出來的？

由 Salesforce 資安團隊開發的 **JA3** 演算法，其原理是將 `Client Hello` 中最具軟體特徵的 5 個核心欄位依序以逗號 `,` 串聯成字串，多個值之間以破折號 `-` 分隔，最後計算 **MD5 雜湊**：

```
[JA3 原始字串結構]
SSLVersion,CipherSuites,Extensions,EllipticCurves,EllipticCurvePointFormats

範例原始字串：
771,49195-49199-52393-52392,0-23-65281-10-11-35-16,29-23-24,0

  │
  ▼ (計算 MD5 雜湊)
JA3 Hash: 6734f37431670b3ab4292b8f60f29984 (這就是唯一的指紋代碼！)
```

- **為什麼有效？**：普通用戶很難自行修改底層加密通訊庫的 Cipher Suite 順序或支援的 Extensions。Python `requests`、PowerShell `Invoke-WebRequest`、Go 編譯的惡意程式與 Chrome 瀏覽器，即便存取同一個網址，其 JA3 指紋也截然不同！

| **Server Hello 返回的數位憑證為「自簽名（Self-signed）」** | **臨時搭建的 C2 伺服器或未授權代理**：<br>攻擊者為節省成本或規避驗證，在 C2 伺服器上自簽憑證，頒發者（Issuer）與主題（Subject）完全相同或均為隨機亂碼。 | • **影響**：惡意外部伺服器連線。<br>• **優先級**：高（封鎖目標 IP 並檢查端點是否忽視憑證錯誤）。 |
| **SNI（Server Name Indication）與憑證 SAN 網域名稱衝突** | **Domain Fronting（網域前置偽裝）**：<br>攻擊者在 SNI 填寫合法高信譽網域（如 `ajax.aspnetcdn.com`），藉此繞過防火牆白名單，但實際在加密層請求連往惡意 CDN 後端。 | • **影響**：防火牆被騙過，惡意流量穿透邊界。<br>• **優先級**：高（啟用支援 CDN 深度解密或主動偵測 SNI 不一致之防護）。 |
| **罕見或淘汰的加密套件（如 SSL 3.0 / 支援 RC4 / MD5）** | **古老殭屍網路或 Legacy 系統弱點**：<br>老舊惡意程式代碼長期未維護，仍使用已被廢棄十幾年的不安全通訊協定。 | • **影響**：存在通訊被監聽或中間人攻擊風險。<br>• **優先級**：中（協同 IT 清查並停用弱加密套件支援）。 |

### 3.1 Wireshark 顯示過濾器精準語法

#### 語法 1：僅過濾出所有客戶端連線發起的 Client Hello 封包
```wireshark
# 篩選 TLS 握手類型為 1 (Client Hello) 的封包
tls.handshake.type == 1
```

#### 語法 2：提取 SNI 伺服器名稱（看它到底想連去哪個網址）
```wireshark
# 篩選所有帶有 SNI 擴展的連線，並顯示其連線目標域名
tls.handshake.extensions_server_name
```

#### 語法 3：過濾出異常的自簽名憑證或憑證異常封包
```wireshark
# 篩選包含憑證傳輸 (Certificate) 的 Server 回應
tls.handshake.type == 11
```

#### 語法 4：在 Wireshark 中直接顯示與過濾 JA3 字串
> 💡 *提示：Wireshark 3.x 以上版本原生支援 JA3 計算（需至 Preferences ➔ Protocols ➔ TLS 勾選 `Enable JA3 calculation`）*
```wireshark

tls.handshake.ja3.hash == "6734f37431670b3ab4292b8f60f29984"
```

### 3.2 Python 即時計算 PCAP 的 JA3 指紋腳本

使用 Python 搭配 `scapy` 或直接解析 hex 酬載，在終端機批量計算封包內的 JA3 指紋：

```python
import hashlib

def calculate_ja3(version: int, ciphers: list, extensions: list, curves: list, point_formats: list) -> str:
    # 按照 JA3 標準：版本,加密套件,擴展,橢圓曲線,曲線格式
    # 注意：需排除 GREASE 填充碼 (如 0x0a0a, 0x1a1a... 等以 0xa 結尾的保留值)
    def is_grease(val):
        return (val & 0x0f0f) == 0x0a0a and (val >> 8) == (val & 0xff)

    clean_ciphers = [str(c) for c in ciphers if not is_grease(c)]
    clean_exts = [str(e) for e in extensions if not is_grease(e)]
    clean_curves = [str(crv) for crv in curves if not is_grease(crv)]
    clean_pts = [str(p) for p in point_formats]

    ja3_string = f"{version},{'-'.join(clean_ciphers)},{'-'.join(clean_exts)},{'-'.join(clean_curves)},{'-'.join(clean_pts)}"
    ja3_hash = hashlib.md5(ja3_string.encode('utf-8')).hexdigest()
    return ja3_string, ja3_hash

# 測試計算
sample_ciphers = [49195, 49199, 52393, 52392]
sample_exts = [0, 23, 65281, 10, 11]
sample_curves = [29, 23, 24]
sample_pts = [0]

raw_str, md5_fingerprint = calculate_ja3(771, sample_ciphers, sample_exts, sample_curves, sample_pts)
print(f"JA3 原始字串: {raw_str}")
print(f"JA3 MD5 指紋: {md5_fingerprint}")
```

### 3.3 Zeek (Bro) 日誌快速威脅獵捕

在大型企業或 SOC 中，Zeek 會自動將所有 TLS 握手解析並記錄至 `ssl.log`：

```bash
# 1. 抓出連線次數最高、但只出現在少數端點的罕見 (Rare) JA3 指紋（威脅獵捕常用技巧）
cat ssl.log | zeek-cut ja3 id.resp_h server_name | sort | uniq -c | sort -n | head -n 20

# 2. 比對惡意已知 JA3 雜湊清單
cat ssl.log | zeek-cut ts id.orig_h id.resp_h ja3 | grep "6734f37431670b3ab4292b8f60f29984"
```

## ⚖️ 第四動：研判分水嶺——正常軟體更新 vs 惡意偽裝？

在日常分析中，Google Chrome 或 Edge 瀏覽器每升級一個大版本，其 JA3 指紋就可能改變；此外，現代瀏覽器普遍採用 **GREASE（故意隨機填充）** 機制以防止協議僵化。你該如何區分真偽？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | NDR 系統警報特定連線的 JA3/JA4 指紋命中已知黑客工具情資（Threat Intel Hit）。 |
| **Q2. 來源實體**（誰/哪個 IP 發起的？） | `src_ip` 是內部伺服器、開發者電腦（常使用 Python/curl 易誤報），還是一般財務/行政人員主機？ |
| **Q3. 目標主機**（連線的外部伺服器是誰？） | 檢查 SNI 與外部 IP：是知名服務（如 `*.github.com`、`*.microsoft.com`），還是剛註冊的動態 DNS 域名或純 IP 直連？ |
| **Q4. 軟體矛盾**（身分宣告與握手指紋是否矛盾？） | 在端點比對該連線的 Process Name 與 HTTP User-Agent：進程為 `svchost.exe` 或 `powershell.exe`，但指紋卻偽裝成 Safari/Chrome？ |
| **Q5. 憑證可信度**（對端伺服器的數位憑證合法嗎？） | 檢查 Server Certificate：是否由受信任的公有 CA（DigiCert, Let's Encrypt）頒發？主體欄位是否有隨機雜湊特徵？ |
| **Q6. 連線頻率**（通訊行為是否具備心跳特徵？） | 檢視該 TLS 連線的間隔（Interval）：是否呈現極度精準的週期性（例如每 60 秒一次），符合 C2 Beaconing（心跳）特徵？ |
| **Q7. 橫向波及**（全網還有誰在發送相同指紋？） | 搜尋全網 Zeek/SIEM 日誌，該惡意 JA3 是否同時在多台互不相關的電腦上出現？ |
| **Q8. 處置動作**（下一步是什麼？） | 1. 於 NGFW/WAF 阻斷該 JA3 指紋與目標 IP；2. 端點 EDR 抓取發起該 TLS 連線的具體二進位檔案進行隔離分析。 |

## 🛡️ 第五動：處置與阻斷 SOP (Mitigation & Hardening)

當確認為惡意 TLS C2 連線時，依循以下步驟進行緊急阻斷與加固：

### 1. 網路層快速阻斷（Network Containment）
- **防火牆 JA3 阻斷**：若邊界設備（如 Fortinet, Palo Alto, Cloudflare）支援 JA3/JA4 識別，直接建立安全規則丟棄該惡意指紋的所有連線。
- **目標阻斷**：在核心交換器與邊界防火牆直接阻斷目標 IP 與惡意 SNI 域名。

### 2. 端點取證與進程斬斷（Endpoint Forensics）
在目標端點執行 PowerShell，將網路連線與本機檔案路徑進行強關聯：

```powershell
# 1. 找出連往外部可疑 IP (例如 198.51.100.23) 的本機進程 PID
$MaliciousIP = "198.51.100.23"
$Connection = Get-NetTCPConnection | Where-Object { $_.RemoteAddress -eq $MaliciousIP }

# 2. 透過 PID 追查具體執行的惡意程式路徑與命令列
$Connection | ForEach-Object {
    $proc = Get-Process -Id $_.OwningProcess
    [PSCustomObject]@{
        PID         = $proc.Id
        ProcessName = $proc.ProcessName
        Path        = $proc.Path
        StartTime   = $proc.StartTime
        CommandLine = (Get-CimInstance Win32_Process -Filter "ProcessId = $($proc.Id)").CommandLine
    }
}
```

## 📋 過關驗收檢查點 (Mastery Checklist)

不看筆記，試著回答以下 5 個實戰問題。若都能回答，代表你已徹底掌握 TLS 加密流量分析：

- [ ] **Q1**：HTTPS 流量明明是完全端到端加密的，為什麼分析師還能在不解密的情況下，僅憑「Client Hello」封包就精準判定連線發起者是 Python 腳本還是真實的 Chrome 瀏覽器？
- [ ] **Q2**：JA3 演算法串接的 5 個核心參數分別是什麼？為什麼它刻意「不」把 Client Random 隨機數或 SNI 域名本身納入計算？
- [ ] **Q3**：什麼是「網域前置（Domain Fronting）」？攻擊者是如何利用 TLS 握手時的 SNI 與加密後 HTTP 標頭中的 `Host:` 不一致，來欺騙企業防火牆的？
- [ ] **Q4**：現代瀏覽器（如 Chrome）在 Client Hello 中引入的 **GREASE 機制** 是什麼？如果不進行過濾，為什麼會導致同一款瀏覽器每次連線算出來的 JA3 指紋都完全不同？
- [ ] **Q5**：新一代的 **JA4 指紋**（JA4+）相比傳統的 JA3 做了哪些重大架構升級？為什麼它能大幅解決 TLS 1.3 與跨平台誤報問題？
